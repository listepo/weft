# Проверка качества

Проверка измеряет, насколько надёжно языковые модели читают и пишут Weft, по сравнению с тремя форматами, которые модели можно было бы дать вместо него: семантический HTML, компонент React JSX и JSON A2UI. Это основание для решения «продолжать или остановить» в задаче T8 и регрессионная проверка каждого следующего изменения формата, праймера или ядра. Стенд находится в `bench/`.

## Что измеряется

**Корпус.** Двенадцать эталонных экранов в `corpus/` (вход, регистрация, настройки, таблица, вкладки, диалог подтверждения, шаг мастера, результаты поиска, список дел, профиль, меню, состояние ошибки). Каждый экран записан во всех четырёх форматах с тем же содержанием, структурой, состояниями, привязками и действиями и снабжён моделью данных. Как написаны форматы, объясняет `corpus/README.md`.

**Задачи.** В `corpus/tasks.json` 60 задач, по пять на экран:

- 36 задач **правки**: изменение обычными словами («Добавьте флажок „Запомнить меня“, привязанный к `$.remember`, под полем пароля»). Модель возвращает весь обновлённый документ.
- 24 задачи-**вопроса** об экране («Какое действие вызывает ссылка „Забыли пароль?“»). Модель отвечает одной строкой `ANSWER:`.

**Запрос.** Одно сообщение пользователя: короткий праймер формата, модель данных, экран в этом формате и задача. Нет системного запроса и примеров сверх праймера. Размеры праймеров — в `bench/REPORT.md`.

**Проверки.**

- *Допустимость*: ответ на правку разбирается в своём формате без ошибок (Weft: валидатор ядра в строгом режиме; HTML, JSX, A2UI: их разборщики в `bench/src/adapters/`).
- *Успех*: ответ допустим, запрошенное изменение есть (утверждения задачи на общем нейтральном дереве, включая порядок и привязки), и ничего другого не потеряно.
- *Починка*: если ответ на правку недопустим, модель получает ещё один запрос со своим ответом и диагностикой валидатора и ничем больше. То же правило для каждого формата. *Допустимость после починки* и *успех после починки* считают второй ответ.
- *Чтение привязок* (необязательно, `node bench/src/run.ts edit --readback`): после того как ответ на правку стал допустимым, с первой попытки или после починки, модель получает ещё один запрос. В нём перечислены изменившиеся привязки, флаги, события и циклы обычными словами и ничего больше. Отрицательная привязка читается как `true while $.busy is falsy (NOT $.busy)`; `!` значит НЕ. Фразы берутся из нейтрального дерева, поэтому у всех форматов одни и те же слова. *Допустимость после чтения* и *успех после чтения* считают этот ответ. Запуски без флага его не посылают, и в их таблице нет столбцов чтения, так что строки ниже остаются сопоставимыми.
- *Ответ*: последняя строка `ANSWER:`, сравнение без учёта регистра и пробелов. Действие в собственном написании формата (`press:nav.reset` в HTML, `actions.nav.reset()` в JSX) считается этим действием.
- *Выходные токены*: видимый размер первого ответа по данным поставщика; токены рассуждения не входят.

**Выборки.** Каждая задача выполняется три раза для каждого формата и модели. Доли — среднее по всем выборкам; разброс — наименьшая и наибольшая доля одной выборки.

**Критерий (T8).** У Weft должно быть не меньше 95% допустимости с первой попытки и не меньше 99% после одного цикла починки. Успех, размер ответа и отрыв от базовых форматов входят в рекомендацию.

**Цена форматов в токенах.** `run.ts tokens` измеряет сам корпус в байтах и токенах (офлайн-прокси и счётчик Anthropic, если задан ключ). Результаты в `bench/REPORT.md`.

## Как запускать

```bash
# Локальная модель через OpenAI-совместимый сервер LM Studio (lms server start; lms load <model>)
node bench/src/run.ts edit --provider openai --model prism-ml/bonsai-27b
node bench/src/run.ts read --provider openai --model prism-ml/bonsai-27b

# Модели Anthropic (ANTHROPIC_API_KEY); --batch снижает цену вдвое, результаты приходят за часы
node bench/src/run.ts edit [--batch]
node bench/src/run.ts read [--batch]

# Размер корпуса в каждом формате
node bench/src/run.ts tokens

# Перепроверить сохранённые ответы текущими проверками, без вызовов модели
node bench/src/run.ts rescore bench/results/<run>.json
```

Параметры: `--screens a,b`, `--formats weft,html,jsx,a2ui`, `--samples N` (по умолчанию 3), `--concurrency N` (по умолчанию 4), `--base-url` для другого OpenAI-совместимого сервера, `--readback` для хода чтения привязок в запуске правок. Каждый запуск пишет `bench/results/<mode>-<time>.json` (каждый ответ дословно с вердиктом) и сводку `.md`. Запуск, оборвавшийся на полпути, всё равно сохраняет то, что успел.

## Ограничения

- Корпус мал (12 экранов, 60 задач) и написан авторами формата.
- Успех правки судят утверждения задачи; изменение, которое они не покрывают, не проверяется.
- Одна форма запроса; нет системного запроса, вызова инструментов и примеров. Ход чтения привязок — второе сообщение пользователя, и только если задан `--readback`.
- Запуски до строки истории от 2026-10-04 имеют одну выборку, не сохраняют ответы и не знают правила написания действий.
