# Перевірка якості

Перевірка вимірює, наскільки надійно мовні моделі читають і пишуть Weft, порівняно з трьома форматами, які моделі можна було б дати замість нього: семантичний HTML, компонент React JSX і JSON A2UI. Це підстава для рішення «продовжувати чи зупинити» в задачі T8 і регресійна перевірка кожної наступної зміни формату, праймера чи ядра. Стенд лежить у `bench/`.

## Що вимірюється

**Корпус.** Дванадцять еталонних екранів у `corpus/` (вхід, реєстрація, налаштування, таблиця, вкладки, діалог підтвердження, крок майстра, результати пошуку, список справ, профіль, меню, стан помилки). Кожен екран записаний у всіх чотирьох форматах з тим самим вмістом, структурою, станами, прив'язками й діями і має модель даних. Як написані формати, пояснює `corpus/README.md`.

**Задачі.** У `corpus/tasks.json` 60 задач, по п'ять на екран:

- 36 задач **правки**: зміна звичайними словами («Додайте прапорець „Запам'ятати мене“, прив'язаний до `$.remember`, під полем пароля»). Модель повертає весь оновлений документ.
- 24 задачі-**запитання** про екран («Яку дію викликає посилання „Забули пароль?“»). Модель відповідає одним рядком `ANSWER:`.

**Запит.** Одне повідомлення користувача: короткий праймер формату, модель даних, екран у цьому форматі й задача. Немає системного запиту й прикладів понад праймер. Розміри праймерів — у `bench/REPORT.md`.

**Перевірки.**

- *Допустимість*: відповідь на правку розбирається у своєму форматі без помилок (Weft: валідатор ядра в строгому режимі; HTML, JSX, A2UI: їхні розбирачі в `bench/src/adapters/`).
- *Успіх*: відповідь допустима, запитана зміна є (твердження задачі на спільному нейтральному дереві, включно з порядком і прив'язками), і нічого іншого не втрачено.
- *Полагодження*: якщо відповідь на правку недопустима, модель отримує ще один запит зі своєю відповіддю і діагностикою валідатора і нічим більше. Те саме правило для кожного формату. *Допустимість після полагодження* і *успіх після полагодження* рахують другу відповідь.
- *Читання прив'язок* (необов'язково, `node bench/src/run.ts edit --readback`): після того як відповідь на правку стала допустимою, з першої спроби або після полагодження, модель отримує ще один запит. У ньому перелічено змінені прив'язки, прапорці, події й цикли звичайними словами і нічого більше. Заперечна прив'язка читається як `true while $.busy is falsy (NOT $.busy)`; `!` означає НЕ. Фрази беруться з нейтрального дерева, тому в усіх форматів ті самі слова. *Допустимість після читання* і *успіх після читання* рахують цю відповідь. Запуски без прапорця його не надсилають, і в їхній таблиці немає стовпців читання, тож рядки нижче лишаються зіставними.
- *Відповідь*: останній рядок `ANSWER:`, порівняння без урахування регістру й пробілів. Дія у власному написанні формату (`press:nav.reset` в HTML, `actions.nav.reset()` в JSX) вважається цією дією.
- *Вихідні токени*: видимий розмір першої відповіді за даними постачальника; токени міркування не входять.

**Вибірки.** Кожна задача виконується тричі для кожного формату й моделі. Частки — середнє за всіма вибірками; розкид — найменша й найбільша частка однієї вибірки.

**Критерій (T8).** У Weft має бути щонайменше 95% допустимості з першої спроби і щонайменше 99% після одного циклу полагодження. Успіх, розмір відповіді й відрив від базових форматів входять у рекомендацію.

**Ціна форматів у токенах.** `run.ts tokens` вимірює сам корпус у байтах і токенах (офлайн-проксі й лічильник Anthropic, якщо задано ключ). Результати в `bench/REPORT.md`.

## Як запускати

```bash
# Локальна модель через OpenAI-сумісний сервер LM Studio (lms server start; lms load <model>)
node bench/src/run.ts edit --provider openai --model prism-ml/bonsai-27b
node bench/src/run.ts read --provider openai --model prism-ml/bonsai-27b

# Моделі Anthropic (ANTHROPIC_API_KEY); --batch знижує ціну вдвічі, результати приходять за години
node bench/src/run.ts edit [--batch]
node bench/src/run.ts read [--batch]

# Розмір корпусу в кожному форматі
node bench/src/run.ts tokens

# Перевірити збережені відповіді поточними перевірками, без викликів моделі
node bench/src/run.ts rescore bench/results/<run>.json
```

Параметри: `--screens a,b`, `--formats weft,html,jsx,a2ui`, `--samples N` (типово 3), `--concurrency N` (типово 4), `--base-url` для іншого OpenAI-сумісного сервера, `--readback` для ходу читання прив'язок у запуску правок. Кожен запуск пише `bench/results/<mode>-<time>.json` (кожну відповідь дослівно з вердиктом) і зведення `.md`. Запуск, що обірвався на півдорозі, все одно зберігає те, що встиг.

## Обмеження

- Корпус малий (12 екранів, 60 задач) і написаний авторами формату.
- Успіх правки судять твердження задачі; зміну, яку вони не покривають, не перевіряють.
- Одна форма запиту; немає системного запиту, виклику інструментів і прикладів. Хід читання прив'язок — друге повідомлення користувача, і лише якщо задано `--readback`.
- Запуски до рядка історії від 2026-10-04 мають одну вибірку, не зберігають відповіді й не знають правила написання дій.
